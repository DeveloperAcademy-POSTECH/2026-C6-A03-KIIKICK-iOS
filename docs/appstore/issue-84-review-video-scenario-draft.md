# #84 App Review 실제 기기 시연 영상 시나리오 — 초안

상태: **Draft / 촬영 전 검증 필요**  
목적: Guideline 2.1의 화면 녹화 요청에 맞춰 앱 실행부터 일반적인 사용 흐름, 계정 생성·로그인·삭제를 실제 기기에서 보여준다.

## 촬영 조건과 준비

- 제출한 빌드와 동일한 **Release/TestFlight 빌드**를 최신 OS의 실제 iPhone과 실제 Apple Watch에 설치한다. 시뮬레이터와 Xcode Debug 빌드는 사용하지 않는다.
- iPhone 화면 녹화는 제어 센터의 화면 기록을 사용한다. Watch 조작 장면은 실제 Watch를 별도 카메라로 촬영한다. 편집한 영상에서도 실제 기기와 조작 순서를 알아볼 수 있게 한다.
- iPhone과 Watch를 페어링하고, 위치·운동·심박 권한을 허용한다. 야외 운동장에서 실제 GPS 기록이 가능한 시간을 확보한다.
- 화면 기록을 시작하기 **전에** 앱을 완전히 종료한다. 녹화 첫 장면은 홈 화면에서 KIIKICK 아이콘을 눌러 실행하는 장면이다.
- 심사용 계정 A에는 분석을 완료한 경기와 댓글 시연에 쓸 경기 기록을 준비한다. 가입·탈퇴 시연에는 별도 계정 B와 수신 가능한 이메일을 준비한다. 계정 B를 삭제한 뒤에도 계정 A는 심사자가 사용할 수 있어야 한다.
- 이메일 인증 코드와 비밀번호, 개인 이메일 주소는 영상 공개 범위를 고려해 가린다. 심사 메모에는 유효한 계정 A의 로그인 정보를 별도로 제공한다.

## 본편: 일반적인 사용 흐름

| 순서 | 기기 | 화면과 조작 | 영상에서 확인할 것 |
| --- | --- | --- | --- |
| 1 | iPhone | 앱 아이콘을 눌러 실행한다. 로그인 화면에서 심사용 계정 A로 로그인한다. | 앱 실행, 로그인, 홈 진입 |
| 2 | iPhone | 홈에서 새 경기 버튼을 누르고 운동장을 선택하거나 등록해 경기를 준비한다. | 운동장 준비와 Watch 연동 안내 |
| 3 | Watch | 준비 상태에서 `경기 시작`을 누른다. 카운트다운 이후 운동을 시작한다. | 실제 Watch에서 경기 기록이 시작됨 |
| 4 | Watch | 진행 화면에서 골 또는 어시스트를 기록하고 `쿼터 종료`를 누른다. 포지션을 고른다. | 타이머, 이벤트 기록, 포지션 입력 |
| 5 | Watch | `경기 종료`를 누른다. iPhone으로 기록이 전송될 때까지 기다린다. | 경기 종료와 기기 간 전달 |
| 6 | iPhone | 분석 탭에서 새 경기 카드를 연다. 필요한 설정을 확인하고 `분석 보기`를 누른다. | 분석 준비 → 업로드 → 분석 상세 |
| 7 | iPhone | 상세에서 쿼터 통계, 히트맵, 스프린트 맵과 타임라인을 차례로 보여준다. 스프린트가 없는 기록이라면 빈 상태 메시지도 보여준다. | 핵심 분석 기능과 빈 기록 처리 |
| 8 | iPhone | 홈으로 돌아가 경기 수·이동거리·칼로리·추세를 보여준다. | 실제 경기 기록에 따른 홈 통계 |
| 9 | iPhone | 경기 상세의 댓글 시트를 열어 댓글을 작성하거나 기존 댓글을 보여준다. | 사용자 작성 콘텐츠의 실제 동작 |

> 촬영 중 운동장 안에서 실제 위치 기록을 확보한다. 기록 시간이 짧거나 GPS가 잡히지 않아 히트맵·스프린트가 비어 있다면, 사전에 준비한 실제 경기 기록을 사용해 분석 화면을 이어서 보여준다. 기능을 실제보다 동작하는 것처럼 보이도록 합성하지 않는다.

## 별도 장면: 가입과 계정 삭제

1. 앱을 종료했다가 아이콘을 눌러 다시 실행한다. 로그아웃 상태에서 `회원가입`을 선택한다.
2. 계정 B의 이메일 인증 → 비밀번호 → 나머지 온보딩 단계를 완료한다. 인증 코드와 비밀번호는 화면에 노출되지 않게 한다.
3. 가입 완료 후 로그아웃하고, 같은 계정 B로 로그인해 로그인 기능을 확인한다.
4. `마이페이지 → 계정 관리 → 회원 탈퇴`로 이동한다. 경고 문구를 보여주고 확인해 실제 탈퇴를 완료한다.
5. 계정 B로 재로그인이 되지 않는지 확인한다. 이후 심사용 계정 A의 유효성을 다시 확인한다.

계정 A를 삭제하지 않는다. 가입용 이메일 인증이 실제 기기에서 실패하면 그 원인을 해결한 뒤 다시 촬영한다.

## 촬영 전 해결·확인 항목

- **댓글 신고·사용자 차단:** 현재 앱 코드에서는 댓글 작성은 확인되지만 신고·차단 UI는 확인되지 않았다. Apple은 사용자 작성 콘텐츠가 있다면 신고·차단 장면을 요구한다. 해당 기능을 구현·검증하기 전에는 영상이나 심사 답변에서 제공한다고 주장하지 않는다.
- **개인정보 처리방침:** #84의 별도 작업 항목이다. 공개 URL과 앱 내 연결 위치를 확정하고, 실제 기기에서 링크가 열리는지 확인한다. 저장소의 정책 문서에는 운영자·문의 URL 등 미확정 표시가 남아 있어 그대로 공개하면 안 된다.
- **스프린트 빈 상태:** #84의 별도 작업 항목이다. 스프린트가 없는 실제 기록에서 안내 문구가 보이는지 확인한다.
- **유료 기능:** 현재 빌드에 유료 콘텐츠나 결제가 없다면 녹화 장면을 추가하지 않고 심사 메모에 해당 없음으로 명시한다. 실제 배포 빌드에서 재확인한다.
- **지역별 차이·외부 서비스·규제 자료:** 영상보다 심사 메모에 정확한 운영 정보를 기입한다. 서버, 이메일 인증, Apple HealthKit 및 위치 서비스 사용 범위를 운영 담당자와 확인한다.
- **제출 전 검수:** 제출한 빌드의 버전, 실제 기기/OS, 화면 녹화 링크 접근 권한, 데모 계정 로그인 가능 여부, 영상 속 개인정보 노출 여부를 확인한다.
