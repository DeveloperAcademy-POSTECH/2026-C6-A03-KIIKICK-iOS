# #71 알림 셀 라우팅

- 이슈: https://github.com/DeveloperAcademy-POSTECH/2026-C6-A03-KIIKICK-iOS/issues/71
- 브랜치: `feat/#71-notification-routing`

홈 알림 버튼과 알림의 분석 이동은 AppRouter의 홈 NavigationPath를 사용한다. 분석 탭의 경로를 대신 변경하지 않는다. 준비 → 분석 중 → 상세 전환은 준비·분석 중 화면만 교체하므로, 상세에서 뒤로 가면 알림 목록으로 돌아온다. 분석 중 다른 탭을 선택해도 원래 탭 경로만 변경하고, 작업이 취소되거나 같은 스택에 다른 경로가 쌓이면 예약된 이동을 하지 않는다.

분석 결과 알림은 해당 기록을 포함하는 전체 경기의 쿼터를 표시한다. 목록과 알림이 기존 ‘같은 운동장·직전 쿼터 종료 후 10분 이내’ 그룹 기준을 공유한다. `WorkoutRecord.hasViewedAnalysis`의 기본값은 false이고, ‘분석 보기’에서 포지션·공격 방향과 함께 저장한다. 모든 쿼터가 저장 완료 상태일 때 이후 알림은 상세로 바로 이동한다. 준비 화면을 단순히 열었다가 뒤로 가는 것으로는 완료 처리하지 않는다. 새 쿼터가 추가되면 그 쿼터 설정도 확인한다.

댓글 알림에는 대상 `matchID`를 추가했다. 사용자 결정에 따라 알림 목록 위에 해당 경기의 분석 상세를 push하고 기존 댓글 시트를 `.large`로 펼친다. 삭제되었거나 로컬에 없는 대상은 시스템 알림으로 안내한다. 유효한 알림을 열면 메모리 알림의 읽음 상태를 갱신한다.

댓글 알림의 서버 수신·목록 조회, 댓글 내용 API, 특정 댓글 스크롤은 이번 라우팅 변경 범위가 아니다. 기존 댓글 목록은 API 미연동으로 비어 있다. 서버 대상 경기를 이 기기의 기록으로 찾지 못하면 임의의 경기를 열지 않는다.

## 검증

- `scripts/validation/check-notification-routing.sh`: 테스트 전용 임시 저장소와 실제 AppRouter·WorkoutRecord·AnalysisEntry 빌더로 경기 묶음, 첫 진입/저장 후 재진입, 댓글 경로, 스택 복귀, 다른 탭·다른 경로 보호, 프로세스 재시작 후 저장 여부 확인. 앱에는 샘플 알림을 추가하지 않는다.
- 이전 `WorkoutRecord` 모델로 만든 저장소를 새 모델로 열어 `hasViewedAnalysis == false` 기본값과 기존 기록 보존을 확인.
- iOS/watchOS Simulator Debug·Release 빌드.

## Design Gaps — 알림 라우팅

- 🟡 삭제·미보유 경기 안내의 별도 시안은 미확인으로, 기본 시스템 alert를 사용한다.
- 기존 알림 셀·준비·상세·댓글 시트를 재사용하며 새 디자인 토큰은 추가하지 않았다.
